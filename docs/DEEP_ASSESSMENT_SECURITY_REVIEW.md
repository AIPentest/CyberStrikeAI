# 深度测评安全复查

范围：独立测评的 HTTP/API → 调度 → 模型输出 → MCP 执行，以及审批、证据发布、项目隔离和前端异步交互。采用源码数据流审查与本地回归夹具，未执行真实目标攻击。

## 已修复的边界问题

| 问题 | 触发条件及影响 | 修复与回归 |
|---|---|---|
| 审批请求未绑定具体调用 | 旧页面/重放请求只携带步骤 ID，同一步骤已产生下一次待审批调用时，可能批准非用户所见的调用 | 服务器生成 approval_id，绑定调用参数摘要、执行者；旧编号返回 409。恢复时重新生成待审编号；执行前重新检查审批人有效性与权限；请求、决定和执行日志保留审批编号/摘要/操作者关联 |
| HITL 权限范围未独立验证 | 同时拥有全局 assessment:write 和仅自身范围的 hitl:write，可能审批其他人的任务 | 两个权限分别检查各自资源范围；审批权限/授权被撤销后，旧批准不能继续使用 |
| 自动放行记录未跟随策略变化 | 暂停后全局策略改为需要人工审批，旧自动放行状态可能继续有效 | policy/manual 授权分别处理，执行前检查当前策略；切换执行者或恢复运行使旧授权失效 |
| 运行中证据更新与人工发布竞态 | 人工看到的证据与提交时同一数组位置的内容已不同 | 每份展示证据附带 revision；发布必须携带匹配版本，内容变化返回 409 |
| 无 owner 的资产被低权限去重回写 | 非全局写用户提交已有无 owner 资产的去重键，原逻辑可能更新该记录 | 非全局导入必须匹配所有者；显式全局操作仍可更新。共享导入入口一并修复 |
| 项目边界与去重不一致 | 绑定项目的工具修改其他项目资产，或全局角色通过去重把另一项目记录重新绑定 | MCP 资源与目标项目约束统一检查；项目内去重在同一 SQLite 事务核对已有记录归属 |
| 暂停与后台工具提交竞态 | 工具服务会解耦请求上下文，暂停时若仅取消等待而尚未关闭任务执行入口，可能继续接收新的后台动作 | 暂停/停止返回前同步关闭本地进程入口和 MCP worker 租约；截止时间也关闭入口；取消上下文不得再提交工具 |
| 前端切换任务的异步窗口 | 切换后新任务 ID 已生效，旧任务按钮仍显示，可能对错误任务发送控制动作 | 切换即清空详情；控制请求仅绑定当前已加载任务 |

## 资源与一致性加固

- 所有测评 JSON 写入口在解析前限制为 128 KiB；超限返回 413。Cookie 形式的浏览器写操作校验来源；显式 Bearer 集成沿用认证/CORS 策略。
- 模型每轮最多 8 个工具调用，参数最多 64 KiB；调用 ID 要求唯一，压缩过的历史调用 ID 仍被记住。
- 列表查询在数据库侧剔除步骤轨迹与材料，避免每次列表轮询把全部私有模型轨迹加载并复制到 Go 内存。事件分页同时限制条数和约 1 MiB 总量，游标可继续读取。
- 模型渠道和 HITL 策略使用与配置写入相同锁下生成的深拷贝快照，避免热更新读取混用不同版本的配置字段。
- 测评将已授权的项目上下文传递给 MCP，项目资产查询可以使用现有工具，同时保持其他项目隔离；错误结果保留诊断信息，便于规划器解释受阻原因。

## 验证入口

- `internal/assessment/security_test.go`：审批重放、参数与执行者绑定、审批人撤权、策略变化、重复/超量调用、列表及事件分页。
- `internal/handler/assessment_test.go`：权限范围组合、证据版本竞态、超大请求、写操作来源检查。
- `internal/handler/assessment_config_test.go`：并发热更新下配置快照一致且不共享可变映射。
- `internal/app/assessment_security_test.go`：无隐藏会话的真实 MCP/资产工具链、跨项目操作拒绝。
- `internal/database/asset_test.go`：无 owner 资产写保护、项目内去重的原子归属检查。
- 浏览器冒烟脚本：精确审批编号、证据版本提交、切换任务时清除旧控制界面。

这不是全项目不存在漏洞的证明。通用 Shell 和外部 MCP 仍继承其宿主权限；自由文本 scope 不构成网络或文件系统沙箱。任务输出可能包含敏感证据，访问和备份应按运行数据管理。真实模型的提示注入抗性和实际长时效果仍需在授权隔离环境中评估。
