# 启动时自动补齐数据库结构

- Status: Confirmed
- Created: 2026-10-10
- Source: 用户要求启动时自动对比所有表的最新结构，缺表、缺字段自动补齐，不依赖迁移代码列出的字段。
- Confirmed by: 用户（当前对话）
- Confirmation date: 2026-10-10

## 问题与目标

当前会创建缺表，但只检查手写迁移列表中的字段。希望以项目最新表结构定义为依据，在服务接收请求之前检查所有应用管理的表，自动补齐缺表、缺字段。以后新增字段只需更新最新表结构定义，无需再维护同一字段的补齐迁移列表。

## 功能需求

| ID | 需求 | 来源 |
| --- | --- | --- |
| REQ-001 | 每次启动时对比所有应用管理表的最新定义和实际结构。 | 用户要求 |
| REQ-002 | 缺表时自动创建，缺字段时自动补齐，不依赖逐字段迁移列表。 | 用户要求 |
| REQ-003 | 项目实际使用的 SQLite 数据库文件均执行上述检查，逐文件检查项目定义的所有表。 | 范围边界 |

| REQ-005 | 无法安全补齐时停止启动，并报告表、字段和原因。 | 范围边界 |
| REQ-006 | 重复启动不重复添加表或字段，结构检查在依赖相关字段的索引创建及业务访问之前完成。 | 范围边界 |

## 范围与执行边界

- “所有表”指项目定义并管理的表，不包含 SQLite 内部表或其他应用自行添加的表。
- 本次需求是补齐缺表、缺字段；完整的已有类型、默认值及约束变更不纳入自动修复范围。
- SQLite 不能直接添加的字段定义应明确报错，不擅自降低约束或清空已有数据。
- 历史数据回填、外键修正等语义迁移仍需保留；它们与缺字段检查是不同职责。
- 执行范围：项目使用的 SQLite 文件、保留已有数据、补齐失败阻止启动。
