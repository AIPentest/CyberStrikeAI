# 深度测评：持续探索与图记忆

独立于「任务管理」的目标工作台，使用 Pi 执行规划、步骤和验收。侧边栏入口位于「对话」下一行；主页面只展示任务列表及行尾操作；点击任务名称或「详情」进入占满主内容区的任务工作区。新建表单使用右侧抽屉。返回列表、切换页面不会停止后台任务。

## 列表操作与归档

任务行末尾提供「开始 / 继续」「暂停」「详情」「归档」；操作是否可用取决于任务状态及账号权限。开始、暂停在列表内更新状态，不自动打开详情；只有点击详情才进入任务工作区。控制请求使用服务端当前版本，重复点击不会并发提交同一任务的操作。

工作区提供返回列表入口，保留列表筛选、分页和已有深链。资产图和探索图使用更大的画布，节点详情可收起；自动刷新、切换视图和画布尺寸变化会保留缩放与位置。「适应画布」查看全图，「整理布局」重新排列节点。长中文标签自动换行，完整内容在节点详情中查看。

点击详情默认进入运行概览。概览展示规划/独立验收阶段、当前意图、工具运行及已有输出、Pi 原生模型/工具/压缩状态、队列计数、最近进展和下次唤醒。数据来自现有执行回执、Pi 事件及任务账本；刷新不会额外调用模型或启动任务。无变化时不重建正文，定向补充的草稿、焦点和阅读位置保留。

概览统计可直接查看明细：累计 Token 进入上下文与用量，状态、规划轮次进入运行记录；意图总数和状态计数进入对应队列。「待核对」同时包含结果不明和资源停止待确认的意图。事实、关联漏洞统计进入全部记录的第一页，清除之前的筛选和来源定位；当前意图提供来源回执、执行会话及可访问资产的入口。这些跳转只读取记录，不触发测评执行。

整条测评受阻与单条意图受阻分别展示。规划器、独立验收或运行环境失败时，测评可能受阻但受阻意图数为 0；页面直接展示最近的任务级受阻事件及时间，并提供运行记录入口。该原因不会被后续执行收尾记录挤掉，旧数据没有受阻事件时沿用已保存摘要。

节点详情默认使用较宽的阅读栏，可拖动图与详情之间的分隔线调整宽度；键盘聚焦分隔线后，左右方向键调整，Home 或双击恢复默认宽度。「展开阅读」将当前节点铺满工作区，点击「返回图」恢复分栏。摘要、执行说明、原始回执和来源分别展示；正文独立滚动，自动刷新保留阅读位置和已展开的来源，切换节点从顶部开始。窄屏改为上下布局，也可展开阅读。

较大图显示缩略导航，可点击定位，也可聚焦后用方向键平移。节点类型和状态、关系颜色帮助区分链路；选中节点显示其相连关系的文字，位于画布外或缩得过小时自动定位到可读尺度。循环引用的回边保留，只在计算层级时避开，避免整组挤成单列。多个目标资产链接在正文中折叠展示，不占据固定底部操作区。全图仍按节点分页，大图概览不能保证每个节点的文字同时清晰，可选中节点或展开关联分支阅读。

资产范围切换、搜索和图操作集中在工具栏，说明与图例可按需展开。未关联资产或搜索无结果时显示明确提示；共享资产记录可展开查看。节点详情按字段显示资产信息，并保留原始记录和来源跳转。

「归档」保留目标、意图、图、回执、事实和漏洞关联，默认列表隐藏，可切换「已归档」查看和恢复。执行中、清理中或结果不明的任务必须先暂停并完成核对，不能直接归档。恢复归档只回到列表，待执行任务需要手动开始；归档记录不会被重启恢复或新事实唤醒。

## 持续执行

新建填写名称和目标即可。「补充限制与排除项」「验收条件」均为选填，留空或仅有空白字符时沿用目标；填写的补充内容会独立保留。表单提供简短说明与填写示例。模型、角色、项目、并行步骤和重启恢复也可选配。保存为草稿，点击「开始 / 继续」才执行。

**任务没有时间窗口、累计 Token、规划轮数、总步骤数或累计执行分段次数上限。** Token 和轮次保留为观测统计，不触发任务结束。任务围绕验收条件推进，直到完成、用户暂停/停止，或需要用户补充信息、核对结果不明的操作。

一个方向停滞时交还规划器换路；暂时没有新方向或验收仍有缺口时保留状态，进入「等待新进展」并定时重评。临时模型故障退避后继续，没有累计重试次数终止条件；认证、权限等需修复的问题会明确显示。等待期间不保持一个空转的模型请求。

单次工具超时、模型上下文容量、每次规划增量和并行工作数仍按执行环境处理。Pi 在轮边界保存一个执行分段，再恢复同一会话，这些边界不构成整个目标任务的累计上限。

旧版本的预算字段会在升级时移除，原「预算耗尽」记录转换为暂停，等待用户继续；升级不会擅自启动旧草稿、暂停或停止的任务。旧客户端创建请求里的预算参数不再生效，`control/budget` 返回 410，请刷新页面。

## 探索图与记忆

「探索图」记录以下节点及其关系：

| 节点 | 来源与用途 |
| --- | --- |
| 目标 | 用户提供的目标、范围、验收条件 |
| 探索步骤 | 规划器的具体方向与依赖 |
| 观察 | 阶段检查点、步骤结果和验收缺口，保留原文 |
| 执行回执 | 实际工具调用结果；失败与结果不明状态分别保留 |
| Pi 摘要 | 原生 `compaction_end` 产生的会话摘要，关联原生会话条目 |
| 历史归档 | 冷历史的引用索引，可展开原步骤和相关证据 |
| 人工线索 | 已保存的用户补充，作为用户输入单独标识 |

步骤通过 `depends_on` 建立执行依赖，通过 `source_ids` 引用启发本次探索的观察、回执或摘要。源节点必须属于同一测评。状态变化和观察节点在同一 SQLite 事务提交；原始调用回执和对应节点也在同一事务提交。

借鉴 ARTEX 的冷热分层：活跃方向及其依赖、证据祖先保持可见。已经完成或撤下、连续多轮不参与活跃链路的历史步骤，按引用折叠为归档节点。新方向再次依赖旧步骤或旧证据时，相关链路会重新显示。折叠不删除原步骤、原始观察或工具结果，不改变完成条件。

归档按真实依赖/证据分支分组，并持久化连续冷却的起始轮次；重新被引用后重新计时。已登记漏洞、目标和人工线索不会因来源步骤归档而隐藏，归档的对外关系标明「经归档」。旧版按 ID 批次建立的归档改标「已替代」，原 ID 和成员仍可展开，不删除历史记录。

默认「主链路」收起观察和工具回执，关系标明「经执行记录」；切换「执行记录」或展开分支可查看原文。分页保留跨页引用节点，当前页最多展示 80 个引用；更多关联会明确计数，节点详情提供独立分页的完整上下游列表。跨页引用与归档投影都是视图，原始节点和边保持不变；显示与导航均遵守漏洞读取权限。

会话摘要由 **Pi 原生压缩**生成并沉淀为图中的记忆节点。业务图的冷分支归档保存成员索引及已有结果摘录，不另起一套模型压缩循环。摘要是模型派生的续接材料，证据仍应回查执行回执。

界面支持平移、缩放、适应画布、节点选择、原文分页及归档展开。大图分页面显示，分页大小仅影响本次展示，不限制总节点数；步骤清单也可分页查看。

Agent 可调用：

- `assessment_graph`：查看当前图，传 `scope` 为归档或步骤节点 ID 时展开关联内容。
- `assessment_node`：按 ID 和字符偏移读取完整节点原文与来源。
- `assessment_memory`：检索步骤、图记忆和原始执行过程，包含被折叠的历史。
- `assessment_trace`：分页读取完整执行过程。
- `assessment_checkpoint`：保存当前观察，同时保留 Pi 原生自定义条目。
- `assessment_result`：提交 completed、blocked 或 continue；完成需引用本任务真实成功调用的回执。

## 漏洞管理关联

执行过程中通过 `record_vulnerability` 成功登记的漏洞，按实际执行会话自动关联测评 ID、测评名称、步骤 ID 和步骤标题。只写在检查点或摘要中的观察不会自动生成漏洞。工具和权限沿用当前角色配置。

- **测评 → 漏洞**：在任务工作区的「关联漏洞」中查看本次测评已登记的漏洞，打开漏洞管理详情，或在测评中查看其复现步骤、证据和来源步骤回执。
- **漏洞 → 测评**：漏洞详情显示来源测评和步骤，提供「返回测评步骤」「查看步骤与复现证据」入口。链接会定位具体步骤，不受步骤清单当前分页影响。
- **按任务分组**：漏洞管理的任务视图以测评名称展示，内部以测评 ID 分组；同名测评及相同 ID 的批量任务不会混组。任务名称搜索同时支持测评名称，原 `task_id` 参数仍保留批量任务语义；测评可用 `assessment_id` 筛选。

升级会按已有的可信执行会话补建历史关联，不按标题或标签猜测。关联快照随漏洞保存；删除测评或执行会话后，漏洞及其复现内容仍保留，已删除的测评不提供返回入口。

读取测评和读取漏洞分别检查权限。仅分享测评不会自动分享所有漏洞；仅分享漏洞也不会授予来源测评的访问或执行权限。

## 共享资产图、意图队列与事实

任务工作区包含「资产图」「探索图」「意图队列」「事实」「关联漏洞」「证据回执」等视图。原步骤 ID 和漏洞返回链接保持兼容。

- **资产图**从现有资产库投影域名、子域、IP、服务、业务应用和端点。多个测评引用同一资产 ID，不复制一套资产库。共享仍遵守资产权限和测评关联项目；IP 连线表示记录中的关联，不代替 DNS 验证。应用节点来自资产的业务系统字段。
- 在「共享资产库」搜索并关联资产后，可作为本次意图目标。端点保存在服务资产下，按资产、HTTP 方法、路径去重；查询值和 Token 不写入端点身份。图按资产分页，选中服务后可分页读取全部端点；意图可跳转目标资产，资产节点可反查针对该资产的意图。
- **意图**沿用步骤记录，新增 `asset_ids` 和 `priority`（1 优先、默认 100）。`source_ids` 保留派生依据，`depends_on` 控制执行前置条件。队列持久化，按优先级、原有顺序调度；不因并发已满而丢弃待办，也不会抢占正在执行的意图。
- worker 第一次执行时保存所锚定资产的原始快照，续跑继续使用该快照，同时重新检查当前资产访问权限。资产删除后保留任务和证据历史，不能静默改打另一个目标。
- **事实**不可原地改写。`observed` 表示有本意图原始执行回执支持的观察；`inferred` 表示依据现象或既有节点作出的推断。回执必须真实存在、成功完成且属于相应测评和意图，不能用 Pi 摘要或漏洞登记回执替代。事实通过「产出／支持／推导」边进入探索图。
- 资产图的「已有观察证据」只统计当前可读、已关联资产中被 observed 事实引用的数量；不是测试穷尽率、安全率或目标完成证明。

每次规划与独立验收均创建新的 **Pi 原生会话**。预取内容包括目标、队列数量、优先待办、在跑意图、近期事实、资产观察计数和有界图视图。完整队列、原文及冷历史通过工具分页读取，不把全部历史重新拼进提示词。

事实、漏洞及关联资产更新会在事务中递增持久版本。调度器合并轮询间隔内的变化，允许 worker 未结束时重新规划；模型调用期间又出现新变化，过时的规划/完成结论不能提交。等待新进展的任务收到变化后可提前唤醒；手动暂停、取消的任务不会因此自动启动。

新增工具：

| 工具 | 用途 |
| --- | --- |
| `assessment_intents` | 按状态分页读取持久队列和优先级 |
| `assessment_assets` | 查询项目/权限范围内的共享资产图、原始资产和分页端点 |
| `assessment_anchor_assets` | 将已有资产关联到本次测评 |
| `assessment_fact` / `assessment_facts` | 写入不可变事实 / 分页读取事实 |
| `assessment_endpoint` | 用本意图的原始回执登记服务端点，需要资产写权限 |
| `assessment_findings` | 读取本测评可访问的漏洞及复现、复核记录 |
| `assessment_review_finding` | 记录另一意图实际复现后的 confirmed/refuted/inconclusive 结论 |

新资产登记继续复用 `create_asset`，漏洞登记继续复用 `record_vulnerability`。深度测评登记漏洞须传 `evidence_receipt_ids`；普通对话与批量任务保持原来的字段要求。新的测评漏洞先显示已登记、待独立复核；独立复核不能由原报告意图自证，也不能引用原意图回执冒充自己的复现。确认或否定结果同步现有漏洞状态，并保留追加的复核历史。尚有待复核或复核未定的新增漏洞时，测评不能自动验收完成。

这些校验保证来源和执行记录可追溯，不能自动判断每段回显一定支持模型结论，更不承诺零误报。复核者仍须检查完整原文、对照实验及复现条件。历史漏洞会补建「待核对」图节点，不补造回执，也不会自动升级为已验证。

## Pi 与宿主的分工

Pi `SessionManager` 管理会话上下文、原生压缩、工具搜索、Skills、重试和生命周期。固定目标与步骤职责随每段执行保留，最新图态势作为有界自定义消息提供，更多历史通过图工具按需读取。结构化工具桥保留参数/输出 schema、结构化结果、annotations、namespace 和暴露策略，权限与实际执行仍由 Go 宿主处理。

规划、执行、独立验收使用 Pi 会话。规划器每轮从持久态势重建输入，未提交的决定不会作为新计划执行；worker 的执行分段仍恢复同一个 Pi 会话。独立验收结合实际回执判断目标是否完成；模型验收不能替代人工复测。

运行中补充方向先入库，再通过 Pi 原生 `steer()` 投递给活跃执行步骤，恢复后也可回查。协作者需以自己的执行身份继续任务。

意图队列支持单条暂停/继续、优先级调整和定向补充。暂停一条意图只取消其执行上下文，其他意图和规划器继续工作；用户暂停标记持久保存，整任务继续和重启不会自动解除，规划器也不能退休该意图来绕过暂停。继续只恢复这一条的排队状态；整任务若已暂停，仍需手动开始整任务。优先级调整不抢占正在执行的步骤。

「给此意图补充方向」先保存到该意图及探索图，再通过对应 Pi 会话的原生 `steer()` 投递；暂停、排队或尚未绑定会话时保存供续跑使用。定向补充不广播给其他 worker。活跃及自动恢复中的测评只允许当前执行账号定向继续或发送执行指令，协作者可先暂停并以自己的账号继续。

下载的 Markdown 报告包含目标、步骤、事实、人工补充，以及当前账号有权读取的关联漏洞、复现内容和完整复核历史。每条复核绑定其原始回执摘录和可返回测评的链接；摘录不替代完整执行会话。运行中导出属于阶段报告，已登记与已独立确认分别标识。

## 恢复语义

点击「开始 / 继续」后自动规划并执行本测评的待办步骤；点击「暂停」后停止新派发，取消规划器与全部在执行的步骤，等待所管执行资源收尾后显示「已暂停」。自动重试、等待新进展和待恢复状态也可暂停；手动暂停后不会被后台恢复队列或服务重启重新启动。打开页面、查看详情和刷新均不会启动任务。

已停止的测评提供独立的「继续测评」入口，保留已完成步骤、原 Pi 会话及证据；只有用户明确点击才会恢复。仍有结果不明或执行资源尚未确认停止的步骤时，先处理待核对项；仍有待答复问题时进入「待答复」，不派发工作。已完成的测评不能重新执行。

「确认已核对」是独立的核对操作，已停止、已完成的测评也可保存。核对后该步骤从「待核对」筛选中移出，历史记录和原始回执保留，任务保持停止或完成状态。确认窗口打开期间若任务有其他更新，页面会重新读取版本；若该步骤已进入另一轮执行，则要求重新查看回执，避免核对到新的执行。

更新或进程退出若打断停止收尾，重启时会整理残留的执行中意图：可信终态回执沿用，未知结果进入待核对，整条测评保持已停止。资源停止尚未确认或存在待答复问题时不会加入自动执行队列。停止收尾期间，旧页面的暂停请求不能覆盖停止决定，仍在收尾的意图也不能直接归档。

核对列表因处理记录而减少时，分页自动回到仍有记录的一页。控制请求固定绑定点击时的测评；浏览器切换测评后，未提交的请求取消，已经提交的请求结果不会覆盖新页面。

1. 工具派发前提交调用意图，结果落库后才交还 Pi。
2. 已确认回执关联原生助手条目与 tool-call ID。若回执已提交而 Pi 记录未写入就退出，恢复时补回已确认结果。
3. 暂停与停止等待本地执行资源收尾，再从同任务、步骤、会话及工具的终态执行记录核对回执。取消信号本身不等于结果不明；确认已取消的调用保存为取消及错误回执，续跑时交回原 Pi 会话，不伪装为成功。旧版误标的记录在点击开始时同样自动核对。
4. 远端取消未获确认、原始执行回执缺失等情况仍进入待核对，不自动重放。点击待核对状态或详情中的「处理待核对」，可跨分页查看相关步骤、回执及执行会话；人工确认只解除该步骤的核对状态，全部处理完仍需手动开始。
5. 已完成步骤保留，结果明确的中断步骤恢复原 Pi 会话。原会话文件缺失时明确受阻，避免静默从空会话重做。
6. 选择自动恢复时，服务重启可恢复此前正在推进且结果明确的任务；草稿、手动暂停及待核对任务不因此开始。图节点、原生摘要和归档成员均持久保存。

当前调度面向单服务进程。允许范围文字会传给规划与执行，实际工具权限继承角色、平台权限、HITL 和调用拦截；范围文字本身不是网络隔离沙箱。

新数据包括 `deep_assessments`、`deep_assessment_events`、`deep_assessment_calls`、`deep_assessment_nodes`、`deep_assessment_edges`、`deep_assessment_sessions` 和 `vulnerability_assessment_sources`。已有深度测评记录会补建图与会话索引，不恢复已撤回旧模块的 `assessments`/`long_tasks` 历史任务。删除测评会清理其任务、图和调度记录；漏洞来源快照随漏洞保留，执行会话仍按原有会话保留策略处理。

## API 与权限

所有接口需登录，使用 `assessments:read/write/delete` 和 `deep_assessment` 资源范围；执行另校验 `agent:execute` 及会话权限。

| 接口 | 用途 |
| --- | --- |
| `GET /api/deep-assessments/options` | 可用项目、角色与模型渠道 |
| `GET / POST /api/deep-assessments` | 查询列表（`archived=true` 查看归档）/ 创建草稿 |
| `GET / DELETE /api/deep-assessments/:id` | 详情 / 删除非活动测评 |
| `GET /api/deep-assessments/:id?step_limit=50&step_offset=0&runtime=true` | 分页详情与运行概览；`step_order=queue&step_status=needs_review` 定位待核对步骤 |
| `POST /api/deep-assessments/:id/control/:action` | start、continue-stopped、pause、cancel、guidance、answer、retry、reconcile、archive、restore，以及 intent-pause、intent-resume、intent-priority、intent-guidance |
| `GET / POST /api/deep-assessments/:id/assets` | 查看共享/关联资产图，或关联资产；`asset_id` 查询服务端点 |
| `GET /api/deep-assessments/:id/intents?status=&offset=0` | 优先级队列和状态计数 |
| `GET /api/deep-assessments/:id/facts?confidence=&offset=0` | 分页读取观察/推断事实 |
| `GET /api/deep-assessments/:id/graph?scope=&view=summary&limit=80&offset=0` | 主链路或 `view=full` 执行记录；包含分页边界计数及引用 |
| `GET /api/deep-assessments/:id/graph/node?node_id=…&offset=0&links_offset=0` | 原文及独立分页的上下游关系 |
| `GET /api/deep-assessments/:id/vulnerabilities?limit=20&offset=0` | 当前账号可读的关联漏洞 |
| `GET /api/deep-assessments/:id/vulnerabilities/:vulnerabilityId` | 属于该测评的漏洞详情和来源步骤 |
| `GET /api/deep-assessments/:id/steps/:stepId` | 单个步骤，用于跨分页定位 |
| `GET /api/deep-assessments/:id/events?after=0` | 增量事件 |
| `GET /api/deep-assessments/:id/receipts?offset=0` | 工具回执 |
| `GET /api/deep-assessments/:id/report` | 包含当前状态及缺口的阶段报告 |

控制请求携带 `revision`。核对使用 `reconcile`，传 `step_id` 和 `reconciled:true`；资源清理未确认另需 `cleanup_confirmed:true`。兼容旧客户端通过 `retry` 提交核对，但不会自动开始执行。`continue-stopped` 仅用于用户明确继续已停止测评，另检查执行权限。

单条意图操作另传 `step_id`；调整优先级传 `priority`（1–1000），定向补充传 `message`。响应的 `guidance_delivered` 表示是否已投递到当前 Pi 会话；未投递时已保存，后续继续生效。

## 验证边界

隔离回归验证旧预算不生效、超过原步骤/分段上限仍能继续、冷分支折叠与活跃链路恢复、原始 Pi 摘要回查、图来源隔离、重启恢复和真实 Pi SDK 模拟模型闭环。浏览器回归检查无预算表单、图渲染、节点读取、抽屉交互、桌面与手机布局，原批量任务回归仍保留。

这些测试验证执行机制，不等于已完成真实目标的多天效果、发现质量或成本对照试验。
