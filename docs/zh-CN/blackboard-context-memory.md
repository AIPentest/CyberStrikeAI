# Pi 长上下文与项目续接记录

Pi 的 SessionManager 保存完整 JSONL 会话和压缩条目，工作上下文由当前分支及压缩结果重建。模型上下文窗口与完整会话记录是不同的数据层。

## 自动续接

已绑定项目、启用项目黑板和上下文续接时，成功的 `compaction_end` 事件会保存一条 `note/context-*` 记录。记录包含摘要、来源会话、代理范围、Pi 会话文件和真实条目 ID。相同会话／代理更新同一条工作记录。

数据库强制使用 `category=note`、`confidence=tentative`，不会自动置顶或将摘要升级为已确认事实。写入和项目绑定校验在同一 SQLite 语句内完成；运行期间改绑或解除项目后，旧运行不能写入原项目。

需要细节时，通过已有黑板工具和原始会话／工具记录核对。摘要可能遗漏信息，不能用它证明漏洞、替代执行证据或扩大用户范围。

## 来源区分

Pi 原生压缩摘要不是新的用户指令。导出为通用对话轨迹时，摘要标为宿主生成的助手工作上下文；重新导入时不会提升为 user 消息。读取旧轨迹时，仅从宿主结构化元数据恢复用户原文账本；生成摘要、执行模板和助手伪造的账本文本不作为原始用户要求。

用户真正输入的 `<summary>` 等字面文本仍是用户内容，不按关键词删除。旧摘要来源标记只用于历史数据读取，不包含旧框架执行代码。

## 运行与清理

- 相同会话的主代理和子代理各自维护 Pi 会话范围。
- 会话目录按会话存储键分组；删除对话会清理该对话的全部 Pi 子会话，不影响其他对话。
- 进程中断后未提交的工具结果保持不确定，先核对执行记录，再决定下一步。
- 阶段成果和正式发现仍由已有工具与评估复核流程维护。
